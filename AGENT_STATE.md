## Notes for future runs (not commitments — do not widen a diff for these)

- `relational.py`'s `_expression` raises a bare `ValueError("Unsupported
  expression type CosineDistance")` when a distance operator reaches the
  Polars evaluator (e.g. a `RANK() OVER (... ORDER BY v <=> :q)`), which
  leaks an untranslated exception through the DBAPI boundary that
  `errors.translate` is supposed to own. Small, separate fix.
- `ruff.toml` sets `fix = true` / `unsafe-fixes = true` globally, so a bare
  `uv run ruff check .` **rewrites files**. Always use `--no-fix` when
  taking a baseline.
- CHANGELOG.md is generated by git-cliff from conventional commits — do not
  hand-edit it; write the commit message instead.

## Run log

### 2026-09-04 — first run (state file created)

- **Chosen:** #6, sub-step "recognise the pattern; do not yet send the
  Grouping Search call".
- **Rationale:** the author names Grouping Search his "first target for
  server-side delegation", and the inventory turned up a *silent
  mistranslation* of exactly that shape, which made it the highest
  value-per-line item on the list. `_flatten_trivial_subquery` treated the
  window subquery as a trivial relabelling and unwrapped it, so
  `SELECT id, rn FROM (SELECT id, ROW_NUMBER() OVER (PARTITION BY category
  ORDER BY embedding <=> :q) AS rn FROM items) t WHERE rn <= 3` compiled to
  `query(collection_name='items', output_fields=['id','category','rn'],
  filter='rn <= 3')` — the window *and the whole vector search inside its
  `OVER`* discarded, Milvus asked for a field literally named `rn`. Wrong
  rows, no error, in direct contradiction of the project's own "reject
  rather than mistranslate" rule.
- **Result:** flattener no longer unwraps computed projections; new
  `grouping_search()` recogniser in `translate/_common.py` reads the
  Grouping Search parameters off the AST; `_build_select` refuses the
  recognised shape with a message naming `group_by_field`/`group_size`/
  `metric_type`. README's "which Milvus cannot express" claim corrected.
- **Full integration deferred:** sending the call needs the outer `LIMIT`
  mapped onto number-of-groups, `rn` materialised from per-group hit order,
  and the inner `WHERE` pushed into the search filter — over this run's
  size budget, and the recogniser is the primitive it will consume.
- **Opened:** PR [#13](https://github.com/Callix-Tools/milvusql/pull/13)
  (draft). CI green on `c174390` — lint, test (3.12), test (3.13);
  `mergeable_state: clean`.
- **Diff size:** 522 added / 3 removed across 7 files. Of that, ~207 lines
  are source (`_common.py` +169, `ast_to_pymilvus.py` +38), ~202 are the
  new tests, and the rest is README + this file. The source half sits
  inside the per-run budget; counting the journal and tests it does not,

  to grow the *code* half.

  ty + bandit clean), then 302 core unit / 86 sqlalchemy / 57 django after.
